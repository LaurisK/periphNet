# PeriphNet Integration Test Application

Host-side C++ tool that communicates with a live PeriphNet board over USB/UART/UDP,
sends commands, reads decoded Trice output, and runs automated integration tests.
Available as both CLI and GUI (Dear ImGui).

## Prerequisites

- Linux (POSIX APIs: termios, fork/exec, mkfifo)
- C++17 compiler (GCC 9+ or Clang 10+)
- CMake 3.22+
- `trice` binary built in `tools/trice` (or on `$PATH`)
- `til.json` and `li.json` in the project root (generated by `trice insert` during build)

For the GUI (optional):
```bash
sudo apt install libsdl2-dev libgl-dev
```

## Building

```bash
# CLI only (no system GUI deps needed):
cmake -B build_integration -S tests/integration -DBUILD_GUI=OFF
cmake --build build_integration -j8

# CLI + GUI:
cmake -B build_integration -S tests/integration
cmake --build build_integration -j8
```

Output binaries:
- `build_integration/periphnet_cli` -- always built
- `build_integration/periphnet_gui` -- only when SDL2 + OpenGL are found

## Transport Modes

The tool communicates with the board through two channels: **Trice decoding**
(reading TCOBS-encoded diagnostic output) and **command input** (sending ASCII
commands like `help`, `bms start`, etc.). Three transport configurations are
supported:

### USB (default)

Single USB CDC serial port carries both Trice data and commands.
The tool reads raw TCOBS bytes from the port, feeds them through a named FIFO
into the `trice` decoder subprocess, and writes commands back to the same port.

```
Host                              Board
periphnet_cli ----USB CDC----> USART (trice + commands)
              <---USB CDC----
```

```bash
./periphnet_cli --mode usb --port /dev/ttyACM0
```

### UDP

Trice output arrives via UDP (the firmware sends Trice over Ethernet).
Commands are sent over a separate serial port (USB CDC or UART).

```
Host                              Board
periphnet_cli ----UDP:17001---> Ethernet (trice)
              <---UDP:17001---
              ----Serial------> USB CDC (commands)
```

```bash
./periphnet_cli --mode udp --udp-port 17001 --cmd-port /dev/ttyACM0
```

### Serial

Two separate UART connections: one for Trice output (typically USART3 at
460800 baud via a USB-UART adapter) and one for commands (e.g., USART1).

```
Host                                  Board
periphnet_cli ----/dev/ttyUSB0----> USART3 460800 (trice)
              <---/dev/ttyUSB0----
              ----/dev/ttyUSB1----> USART1 115200 (commands)
```

```bash
./periphnet_cli --mode serial \
    --trice-port /dev/ttyUSB0 --trice-baud 460800 \
    --cmd-port /dev/ttyUSB1 --cmd-baud 115200
```

## CLI Usage

```
periphnet_cli [options]

Transport:
  --mode usb|udp|serial   Transport mode (default: usb)
  --port PATH             USB serial port (default: /dev/ttyACM0)
  --trice-port PATH       Trice serial port (serial mode)
  --trice-baud RATE       Trice serial baud (default: 460800)
  --cmd-port PATH         Command serial port (serial/udp mode)
  --cmd-baud RATE         Command serial baud (default: 115200)
  --udp-port PORT         UDP listen port (default: 17001)

Paths:
  --trice-bin PATH        Path to trice binary
  --project-root PATH     Project root (for til.json, li.json, trice)

Tests:
  --list                  List available tests and exit
  --test NAME             Run only named test (repeatable)
  --help                  Show this help
```

### Examples

```bash
# List all tests:
./periphnet_cli --list

# Run all tests via USB:
./periphnet_cli --mode usb --port /dev/ttyACM0

# Run a single test:
./periphnet_cli --mode usb --test help_command

# Run only BMS tests:
./periphnet_cli --mode usb \
    --test bms_start \
    --test bms_all_frames \
    --test bms_voltage_current \
    --test bms_soc_soh \
    --test bms_limits \
    --test bms_charge_flags \
    --test bms_manufacturer \
    --test bms_set_values \
    --test bms_stop

# Override trice binary location:
./periphnet_cli --trice-bin /usr/local/bin/trice
```

Exit code is 0 if all run tests pass, 1 if any fail.

## GUI Usage

```bash
./periphnet_gui
```

The GUI has four tabs:

| Tab | Purpose |
|-----|---------|
| **Settings** | Select transport mode, set port paths, connect/disconnect |
| **Trice Log** | Live auto-scrolling view of decoded Trice output with text filter |
| **Console** | Manual command entry -- type commands and see responses |
| **Tests** | Run all tests, view pass/fail/skip results table |

Connect to the device in the Settings tab first, then switch to other tabs.

## Test Cases

Tests run sequentially. BMS tests share state (sim+reader stay running between
`bms_start` and `bms_stop`).

### General

| Test | Description |
|------|-------------|
| `heartbeat_present` | Verify periodic heartbeat Trice messages arrive within 3s |
| `help_command` | Send `help`, verify all known commands listed |
| `peripherals_command` | Send `peripherals`, verify response |
| `unknown_command` | Send unknown command, verify "Unknown command" error |

### BMS CAN Loopback

These tests require **CAN1 and CAN2 transceivers physically connected** on the
same CAN bus. The BMS simulator transmits Pylontech protocol frames on CAN1, and
the BMS reader receives and parses them on CAN2.

| Test | Description |
|------|-------------|
| `bms_start` | Start simulator (CAN1) and reader (CAN2) at 500 kbps |
| `bms_status_running` | Verify both report running state |
| `bms_all_frames` | All 6 Pylontech frame types received (rxMask=0x3F) |
| `bms_voltage_current` | Default voltage 51.2V and charging current -2.5A |
| `bms_soc_soh` | SOC=85% and SOH=99% |
| `bms_limits` | Charge limit 56.0V, discharge limit 44.8V |
| `bms_charge_flags` | Charge and discharge both enabled |
| `bms_manufacturer` | Manufacturer string "PYLON" |
| `bms_set_values` | Change V/I/SOC/T, verify updated values propagate |
| `bms_set_full_charge` | SOC=100% at float voltage |
| `bms_set_low_soc` | SOC=5% with near-cutoff voltage |
| `bms_frame_count` | Frame counter increments across multiple sends |
| `bms_stop` | Clean shutdown, rx count logged, status=stopped |
| `bms_no_data_when_stopped` | `bms read` rejected when reader not running |
| `bms_restart` | Clean restart with zeroed reader state |
| `bms_restart_send_receive` | Full send+receive cycle works after restart |
| `bms_final_stop` | Final cleanup |

### Destructive (skipped by default)

| Test | Description |
|------|-------------|
| `reboot_command` | Reboots the board (loses connection) |
| `dfu_command` | Enters USB DFU bootloader (loses connection) |

Run destructive tests explicitly: `--test reboot_command`

## How It Works

```
periphnet_cli / periphnet_gui
        |
        v
    +--------+
    | Device  |  High-level: sendCommand(), sendAndExpect(), readLine()
    +--------+
     /      \
    v        v
+---------+ +------------------+
| ITrice  | | ICommandTransport|  Transport interfaces
| Source  | |                  |
+---------+ +------------------+
    |              |
    v              v
+----------+  +----------+
| Serial / |  | Serial   |   Concrete implementations
| USB /    |  | (owned   |   (selected by --mode)
| UDP      |  | or       |
| Trice    |  | borrowed |
| Source   |  | FD)      |
+----------+  +----------+
    |
    v
+---------------+
| TriceProcess  |  Named FIFO + fork/exec of `trice log -p FILE`
+---------------+
    |
    v
  trice subprocess decodes TCOBS -> readable text lines
```

The `trice` subprocess decodes raw TCOBS-encoded bytes into human-readable text.
Each transport source feeds raw bytes into a named FIFO; the trice subprocess
reads the FIFO and writes decoded lines to its stdout, which the tool reads back.
